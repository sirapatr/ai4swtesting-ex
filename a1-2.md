# Activity 1 – Step 2: A specific prompt with context

**Chatbot / model:**  Gemini

## Prompt

```text
Act as a professional software tester and suggest test ideas for the feature delimited by three hashes. All test ideas should be focused on discovering risks that impact the quality characteristics: Functionality, Data Integrity and Security
###
* As a paralegal, in order to store and share legal documents, I want to be able to securely upload documents.
* Acceptance criteria:
  - Upload should support the following common file formats: PDF, DOCX, TXT
  - The maximum file size should be 20MB
  - When a document is uploaded it should give a progress update to the user
  - Once uploaded, the document must initially be only accessible to the person who has uploaded it
  - A report of the upload and whether it was successful or not will be stored in the auditing feature
###
```

## Response

As a software tester, here is a breakdown of test ideas organized by the three targeted quality characteristics to uncover potential risks in the document upload feature.

---

## 1. Functionality Test Ideas

* **Format Compliance & Bypass (Acceptance Criteria 1):**
* **Valid Extensions:** Upload standard `.pdf`, `.docx`, and `.txt` files.
* **Invalid Extensions:** Attempt uploading unsupported formats like `.exe`, `.zip`, `.png`, `.mp4`, `.csv`, `.bat`. Verify clear user-facing error messages.
* **Extension Manipulation:** Rename a `.png` or `.exe` file to `.pdf` or `.docx` and attempt an upload.
* **Extension Case Sensitivity:** Test `.PDF`, `.Docx`, `.TXT` to ensure case insensitivity.
* **Double Extensions:** Test files named `document.pdf.exe` or `contract.txt.docx`.


* **Boundary & File Size Limits (Acceptance Criteria 2):**
* **Exact Boundaries:** Test files at 0 KB (empty file), 1 MB, 19.9 MB, 20.0 MB (exact limit), and 20.1 MB (over limit).
* **Excessive File Sizes:** Attempt uploading multi-gigabyte files to test client-side vs. server-side enforcement.
* **Resource Exhaustion:** Test behavior when uploading multiple 20 MB files sequentially or simultaneously.


* **Progress Indicator Dynamics (Acceptance Criteria 3):**
* **Visual Feedback:** Verify progress bar or spinner appears immediately upon starting upload and updates smoothly from 0% to 100%.
* **Network Fluctuation:** Simulate slow network speeds (3G/2G) to verify progress percentage updates accurately over extended durations.
* **Cancellation & Resumption:** Attempt cancelling mid-upload; verify upload stops, no orphan files are created, and progress UI resets gracefully.
* **Browser Navigation:** Refresh or close the browser tab during upload to test interrupt handling.



---

## 2. Data Integrity Test Ideas

* **Content & Structure Preservation:**
* **File Hash Verification:** Calculate MD5/SHA-256 checksums of local files before upload and compare them with downloaded copies to ensure zero corruption or byte loss.
* **Special Content Encoding:** Test files containing special characters (e.g., Unicode, foreign scripts like Kanji/Arabic, emojis), complex formatting, or embedded macros.
* **Filename Character Encoding:** Upload files with filenames containing spaces, symbols (`#`, `%`, `&`, `/`, `\`), and non-ASCII characters to prevent path manipulation or truncation.
* **Max Length Filenames:** Test extremely long filenames (e.g., 255+ characters).


* **Auditing & Event Traceability (Acceptance Criteria 5):**
* **Audit Event Accuracy:** Verify successful uploads generate an audit record containing correct timestamps, user ID, exact file name, file size, and outcome (`SUCCESS`).
* **Failed Attempt Auditing:** Intentionally fail uploads (e.g., net drop, oversized file, unauthorized format) and verify audit records capture the failure (`FAILED`), along with failure reason/error code.
* **Immutability & Tampering:** Attempt editing or deleting audit log records to confirm audit logs are read-only.
* **Concurrent Operations:** Perform simultaneous uploads from multiple accounts to ensure audit log sequences remain synchronized without lost updates or race conditions.



---

## 3. Security & Access Control Test Ideas

* **Default Privacy & Access Control (Acceptance Criteria 4):**
* **Unauthorized Direct Access (Horizontal Privilege Escalation):** Capture the file URL/ID of an uploaded document and attempt accessing it via direct link from another user account or unauthenticated session.
* **Role-Based Isolation:** Verify paralegals, attorneys, or system admins cannot see the newly uploaded document until explicit permissions/sharing actions take place.
* **Session Expiration:** Attempt downloading or accessing a document using an expired session token.


* **Malicious Payload & File Validation:**
* **MIME-Type & Magic Byte Spoofing:** Change the MIME-type header during upload or modify magic bytes (e.g., inserting a PDF header into an executable payload) to test deep file validation.
* **Malware & Virus Scanning:** Upload a standard test virus payload (e.g., EICAR test file) disguised as a `.pdf` or `.docx` to verify integrated malware scanning catches and isolates the file before storage.
* **XML External Entity (XXE) Attacks:** Upload `.docx` files containing malicious XXE payloads aimed at extracting server configuration or sensitive local files.
* **Path Traversal / Directory Injection:** Name files using path traversal sequences (e.g., `../../etc/passwd.pdf` or `..\..\boot.ini.txt`) to ensure files are stored strictly within designated directories.


* **Data-in-Transit & Data-at-Rest Protection:**
* **Transport Encryption:** Confirm uploads strictly occur over HTTPS (TLS 1.2+) with secure headers.
* **Storage Encryption:** Verify stored files on the server/cloud storage bucket are encrypted at rest using standard encryption algorithms (e.g., AES-256).
